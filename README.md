# 漂流补给站 Drift Depot

一个海岛补给站主题的游戏系统设计作品。通过收集木材与鲜鱼、交付船只订单、升级工具和修复灯塔，呈现一个可以实际操作的资源循环。

作品同时提供规则配置、奖励视频异常流程和本地事件记录，便于理解并检查每一步设计。

**[在线体验](https://wcm666hub.github.io/drift-depot-demo/)** · **[阅读设计文档](./DESIGN.md)**

## 作品内容

- 6 个按顺序解锁的订单，2 种消耗资源和 1 种成长货币。
- 首单直接完成交付与领奖，再引入采集和成长选择。
- 第 2 单后选择升级工具，或保留贝币先修灯塔。
- 自愿选择奖励视频，支持播放完成、提前退出、加载失败和重复奖励回调模拟。
- 调整采集量、灯塔费用及 A/B 奖励方案，导出配置和本轮事件。
- 设计说明展示默认路径计算、当前问题与后续验证计划。

这是虚构产品的流程原型，未接入真实广告或服务端。页面中的时间、收入和事件均为本地模拟，未形成真实用户实验或商业结论。

## 快速体验

打开 index.html，即可在浏览器中体验，无需安装依赖。初始 2 木材足够完成首单；交付并领取奖励后，按下一单的需求采集资源。

体验免费路径时，第 2 单后暂不升级，第 3 单普通领奖后可修复灯塔。重新开始后再尝试升级或视频奖励，可以对比不同选择。

页面导航包括“交互原型”“规则与配置”“数据与验证”“设计说明”。进度保存在本机浏览器；“重新体验”会清除本轮进度。

## 设计发现

默认规则下，免费不升级在第 3 单、105 模拟秒时可以修塔；先升级会提高采集效率，但要到第 4 单才够钱修塔。

提高视频奖励可以增加贝币，却不能跳过“完成至少 3 单”的门槛，而且视频会推进模拟时间。因此当前入口只承诺额外贝币。下一步需要完善修塔后的成长目标和货币消耗，并用真实玩家测试验证价值。

## 项目文件

| 文件 | 用途 |
| --- | --- |
| index.html | 可独立打开的完整交互页面，也是网站入口 |
| shell.html | 页面结构与公开设计说明 |
| engine.js | 订单、资源、奖励和存档状态规则 |
| app.js | 页面交互、本地存档和 JSON 导出 |
| style.css | 视觉样式与响应式布局 |
| config.json | 默认数值配置参考 |
| DESIGN.md | 系统设计、异常规则和验证计划 |
| build.py | 将页面、样式和脚本合并为 index.html |
| test_engine.cjs | 使用 Node 内置模块运行 10 项规则测试 |

修改规则时编辑 engine.js 中的默认配置；config.json 为阅读参考，不是页面运行时读取的配置文件。修改源文件后重新构建 index.html。

## 本地构建和规则检查

在项目目录运行：

    python build.py
    node test_engine.cjs

构建仅使用 Python 标准库；测试仅使用 Node 内置模块。测试覆盖免费与升级路径、资源不足、奖励取整、视频失败和退出、重复结算、60 秒冷却边界、3 次奖励上限、资源上限、刷新恢复和结束状态。

## 网站发布

仓库根目录包含 index.html 和 .nojekyll，可以作为静态网站入口。GitHub Pages 的发布设置选择主分支的根目录。发布后从仓库的 Pages 页面获取实际网站地址。
